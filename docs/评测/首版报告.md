# 核心评测报告

> 本报告只记录真实执行结果，不包含估计数字。商品 Agent 使用 DeepSeek `deepseek-flash`、`temperature=0`、每个任务重复 3 次；API Key 不写入仓库或报告。

## 1. 当前协议

- Core：30 个不同任务，90 次执行；
- 主指标：权威最终状态驱动的任务完成率；
- 稳定性：连续 3 次全部完成的任务数；
- Clarification、Safety、Runtime 和 Recovery 独立报告；
- Blind 在 Core 优化完成前不运行。

## 2. Core Baseline

Core Baseline 尚待本轮真实模型运行。有效结果必须同时满足：

- 场景数为 30、执行数为 90；
- 基础设施错误为 0；
- 协议指纹有效；
- Core 文件哈希与 Manifest 一致；
- 报告给出成功执行数、任务完成率和稳定通过任务数。

真实结果产生后在本节写入，不使用预测值占位。

## 3. 已验证的工程事实

此前真实模型诊断暴露过两类可复现问题：多店请求的参数来源校验误拦截合法目标，以及 Tool 描述与 `AUTO_EXECUTE` 的执行语义冲突。修复后，同一批正常非澄清任务均连续 3 次完成。

安全评测曾在 24 次执行中捕获 8 次危险写入尝试，全部在执行前被权限或 Business Policy 拦截，实际危险副作用为 0。该结果用于说明执行层边界，不并入 Core 完成率。

这些旧结果只作为失败驱动迭代证据，不与当前 30 条 Core 协议计算提升百分比。

## 4. Runtime 与 Recovery

Runtime 和 Recovery 继续由确定性套件验证，不包装成真实用户任务完成率：

```powershell
uv run python -m eval.runtime_suite --dataset eval/datasets/runtime
uv run python -m eval.recovery_suite --dataset eval/datasets/recovery/faults.yaml
```

## 5. 简历数字使用条件

只有在相同 Core 场景、模型配置、Scorer 和重复次数下完成 Baseline 与修正后复跑，才能写成 `X% → Y%`。必须同时保留 `成功次数/90`，并用 Blind 结果检查是否只对固定题目过拟合。
