# Interview Learning Archive Design

## Goal

建立一套面向 EcomAgent 面试准备的会话归档规则。删除或关闭学习会话前，可以生成 Markdown 总结，并将总结按主题、日期和分支组织到：

`C:\Users\L3553\Desktop\学习craft agent`

总结内容聚焦于：

- 用户询问但尚未掌握的技术点；
- 对技术点的解释、类比和示例；
- 当前项目架构与真实实现边界；
- 面试可使用的回答方式；
- 发现的漏洞、误区和后续补强建议。

## Two-level rule files

### Repository-level `AGENTS.md`

位置：当前 EcomAgent 仓库根目录。

职责：当从项目目录发起总结请求时，提醒 Agent 读取目标目录中的完整归档规范，并要求总结只记录当前分支相对于基线的新讨论。

该文件不规定项目代码风格，也不要求每次编码任务都生成总结，只有用户明确要求归档或删除会话时才生效。

### Archive-level `AGENTS.md`

位置：`C:\Users\L3553\Desktop\学习craft agent\AGENTS.md`

职责：规定总结文件的命名、目录、内容结构、分支增量规则、索引维护和质量检查方式。

## Branch-increment model

每份总结必须声明：

- 当前分支名称；
- 总结时间；
- 基于哪个总结或分支作为基线；
- 当前分支新增的讨论范围。

总结时只保留当前分支新增或被当前分支重新澄清的内容。已经存在于基线总结中的知识不重复复制；如果当前分支修正了旧结论，则保留“旧结论 → 新结论”的修正记录。

## Archive layout

推荐结构：

```text
学习craft agent/
├── AGENTS.md
├── 00-总览索引.md
├── 01-项目架构/
├── 02-Agent Runtime/
├── 03-工具与权限/
├── 04-CommerceAdapter与电商接入/
├── 05-MCP与模型调用/
├── 06-EvaluationHarness与测试/
└── 99-待复习问题/
```

文件名使用：

`YYYY-MM-DD__分支名__主题.md`

分支名中的 `/`、空格和特殊字符转换为 `-`，避免 Windows 路径问题。

## Summary format

每个总结至少包含：

1. 当前分支与基线；
2. 本次新增问题；
3. 用户原本不清楚的点；
4. 最终理解；
5. 与当前项目代码的对应关系；
6. 面试表达；
7. 仍未实现或不能夸大的边界；
8. 下一步复习问题。

## Trust and accuracy rules

- 用户的问题、项目代码和已验证测试结果优先于面经中的理想化描述。
- 不把 Craft 项目、其他项目或面试假设误写成 EcomAgent 已实现能力。
- 明确区分“当前已实现”“通过 Mock 验证”“架构预留”“未来计划”。
- 不因总结需要而修改项目代码、创建分支、提交业务改动或删除文件。
- 删除会话前只生成总结，不删除已有总结；若发现重复内容，更新索引而不是覆盖历史记录。

## Success criteria

- 从当前项目发起总结请求时，Agent 能找到目标目录和完整归档规则。
- 新总结只包含当前分支新增内容，并标明基线。
- 总结可以脱离聊天记录独立阅读，用于面试复习。
- 多个分支的总结能够按目录、日期和索引定位。
