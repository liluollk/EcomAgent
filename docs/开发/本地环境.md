# 本地环境搭建

本文档只记录已在本仓库验证过的步骤(Windows 10/11 + Git Bash;macOS/Linux 同理)。

## 前置条件

| 组件 | 已验证版本 | 用途 |
|---|---|---|
| Python | 3.12.6 | 运行时(要求 `>=3.12,<3.13`) |
| uv | 0.12.2 | 依赖管理与命令执行 |
| Docker + Docker Compose | 29.5.3 / v5.1.4 | PostgreSQL 16 + pgvector |
| Node | 24.x | 阶段 4 前端工作台(当前阶段不需要) |

## 步骤

```bash
# 1. 安装依赖(uv 会创建 .venv)
uv sync --all-extras

# 2. 启动 PostgreSQL(首次会拉取 pgvector/pgvector:pg16 镜像)
docker compose up -d postgres
# 等待健康检查通过:
docker compose ps   # 状态应为 Up (healthy)

# 3. 建表
uv run alembic upgrade head

# 4. 运行全量测试
uv run pytest -q
```

测试套件要求显式指定测试库:必须设置 `RUNTIME_TEST_DATABASE_URL`,并额外设置 `RUNTIME_TEST_RESET_ALLOWED=1` 才允许清表。库名必须以 `_test` 结尾,管理连接(建库、终止连接)由同一 URL 只替换库名得到,因此自定义端口上的测试实例不会被清理到默认实例上。三项校验(显式 URL、库名后缀、授权标记)任一不满足都会在连接与 `DROP` 之前抛 `UnsafeTestDatabaseError`;不再有 `localhost:5432/agent_runtime_test` 的内置默认值。

需要与开发库完全隔离时,使用专用容器(项目名固定为 `ecomagent-refactor`,端口 `15439`,不影响默认 Compose 项目):

```bash
export TEST_POSTGRES_PORT=15439
docker compose -p ecomagent-refactor -f docker-compose.test.yml up -d postgres-test
# 若本机只有独立二进制,将 docker compose 写作 docker-compose,参数相同
export RUNTIME_TEST_DATABASE_URL='postgresql+asyncpg://runtime:runtime@127.0.0.1:15439/agent_runtime_refactor_test'
export RUNTIME_TEST_RESET_ALLOWED=1
uv run pytest -q
```

容器内用户 `runtime` 是超级用户,具备建库与 `CREATE EXTENSION vector` 权限;库不存在时由 `tests/conftest.py` 按需创建并执行 Alembic 迁移。开发库 `agent_runtime` 与测试库互不影响。

## 环境变量

复制 `.env.example` 为 `.env` 后按需修改。已使用的变量:

| 变量 | 默认值 | 说明 |
|---|---|---|
| `RUNTIME_DATABASE_URL` | `postgresql+asyncpg://runtime:runtime@localhost:5432/agent_runtime` | 开发库连接串 |
| `RUNTIME_TEST_DATABASE_URL` | 无;必须显式设置,否则持久化测试拒绝运行 | 测试库连接串,库名须以 `_test` 结尾 |
| `RUNTIME_TEST_RESET_ALLOWED` | 无;必须是 `1` | 允许 pytest 清空测试库的显式授权,只用于隔离测试实例 |
| `RUNTIME_MASTER_KEY` | 无(缺失时报 `MasterKeyMissing`) | Secret 加密主密钥,32 字节 Base64;本地可用 `python -c "import os,base64;print(base64.b64encode(os.urandom(32)).decode())"` 生成 |
| `RUNTIME_JWT_SECRET` | 无;缺失时进程启动失败 | JWT 签名密钥,不存在可用的默认值 |

`.env` 已被 `.gitignore` 排除,不要提交真实密钥。

## 常用质量命令

```bash
uv run ruff check runtime agents adapters apps eval tests   # 静态检查
uv run mypy runtime                                          # 类型检查(strict)
uv run pytest -q                                             # 全量测试
uv run pytest tests/persistence -q                           # 只跑持久化测试
uv run alembic downgrade base && uv run alembic upgrade head # 验证迁移可往返
```

## 故障排查

- **连接被拒 / Connection refused**:容器未健康。`docker compose ps` 查看,必要时 `docker compose restart postgres`。
- **`MasterKeyMissing`**:未设置 `RUNTIME_MASTER_KEY`,按上表生成并写入 `.env`。
- **迁移失败**:可 `uv run alembic downgrade base` 后重试;开发库数据可随时 `docker compose down -v && docker compose up -d postgres` 重建(会删除本地数据)。
- **测试库状态异常**:删除 `agent_runtime_test`(pytest 会自动重建)。
