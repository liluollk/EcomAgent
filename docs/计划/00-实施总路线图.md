# Agent Runtime 总体实施路线图 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 从空仓库实现可持久执行、安全可控、可恢复且可评测的 Agent Runtime，并交付 Agent 工作台与商品运营参考 Agent。

**Architecture:** 按“基础设施 → Runtime 内核 → 业务参考实现 → 产品与集成 → Eval 发布门槛”单向推进。每个阶段都必须产生可独立运行的软件、自动化测试和 Git 提交；后续阶段只依赖已验证的公开接口。

**Tech Stack:** Python 3.12, Pydantic v2, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL/pgvector, asyncio, React, TypeScript, WebSocket, MCP, Mem0 OSS, WeKnora, Langfuse, pytest, Playwright

---

## 1. 执行原则

- 使用 TDD：每个行为先写失败测试，再写最小实现。
- 每个 Task 单独提交，提交前运行该 Task 的定向测试。
- 每个阶段结束后运行完整回归，通过后直接进入下一阶段，不等待人工评审。
- Runtime 不导入 `agents/`、`adapters/`、`apps/` 或 `eval/`；架构测试持续防回归。
- 安全不依赖 Prompt；授权、Policy、Confirmation、幂等和回查都使用确定性代码验证。
- 不将 Mock 结果表述为生产指标；所有 Eval 报告保留真实分母和基础设施失败。

## 4. 全局停止条件

遇到以下情况时不能通过“先跳过”继续：

- Migration 无法在空 PostgreSQL 和上一版本数据库上升级；
- Runtime 对上层业务模块出现反向依赖；
- 写操作存在越权、绕过 Confirmation、重复副作用或 `UNKNOWN` 盲目重试；
- ToolResult 未经协议校验、脱敏或 Schema 过滤进入 Context，或结果投影覆盖真实写入事实；
- Context 压缩丢失安全规则、当前意图或活动交互，Memory 删除后仍能被重新召回；
- 工作台事件出现缺口后继续推断状态，或迟到事件把终态逆转为活动态；
- Eval 中出现 401、Provider 不可用、用例跳过或初始状态泄漏；
- Secret 明文进入日志、AgentEvent、ToolResult、Trace 或 Eval 报告。
